## 复核实际修掉了什么

- `len(args)==1` 仅控制参数归一化赋值，不控制两个分支共同到达的最终返回。
- 空参数分支的零参数外部调用不再虚构参数数据流。
- 赋值按实际定义—使用连接，独立赋值不串联，覆盖后的定义取代旧定义；顶层和实际进入的else赋值均参与追踪。
- 原文、参数事实和分支条件从冻结源码重算核对；外部观察ID从独立摘要认证的旧观察回执核对。
- Java 按调用身份、返回上下文与调用者时序拒绝不充分路线；38条旧Jib/Hadoop错误路线保留为排除/未知，不成为消费关系。

独立审查经历三轮反例发现和修正；记录保留在台账中。最终独立聚焦检查54项通过，父任务组合回归63项通过。
Java投影的定向mypy及Ruff通过。源码引用校验、回归和语义审查分别留证，不能互相替代。

## 不能扩大解释的边界

Flask 的入口来自任务明确提供，不是已证明的自动绑定；外部响应、异常、副作用和路径成立条件继续未知。
Jib 是 `reviewed_replay`，入口为 `diagnostic_override`；只认证历史WALA原始证据与当前冻结源码的一条may-state关系。
本轮没有重新构建Java全图，也没有把19个观察映射当作19条语义关系成功。
成本不用于效率结论：Flask产物的 `wall_seconds` 继承上游局部分析计时，不包括本轮读取、重新认证和投影全过程；
其 `projection only` 注释不够准确。Jib重放没有完整成本计时。已冻结的A/B输入保持不变，这两个值不能作为端到端分析成本比较。

输出采用 [`mock-spec.slice-evidence/v1`](../../slice_contract.schema.json)，只表达源码切片、关系、前提、证据、未知和覆盖边界。
没有把原断言升级为具体状态码、调用次数或新Mock实现要求。
