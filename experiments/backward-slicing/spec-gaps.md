# 条件化 Mock 行为规格：现有实现差距表

本文面向 [ADR-0002](../../docs/adr/0002-mock-oriented-backward-evidence.md) 约定的方法：从测试目标出发，通过后向切片和近似符号分析形成共同约束、条件化分支规格、证据与不确定性，并报告全局路径覆盖信息。输出语义以[主规格](../../docs/backward-analysis-spec.md)为准；本次交付是文档，不实现 LLM 约束推理、Mock 代码生成或执行验证。

- Python 的查询与状态投影已经能产生观察关联的值、控制、返回、异常未知、状态候选和排除记录；这些是规格推导的原料，不是已经组合好的执行解释。
- Java 的已发布通用投影仍建立在上下文未匹配的前驱路径上。Hadoop 与 Jib 的真实反例已经否定了其中部分异常／控制关系，详见 [Java 路径独立审查](../../out/mockbench-study/entry-repair-20261111/verification/java-exception-route-review-r5.md)。

## 2026-11-17 局部增量

## 总体判断

现有实现适合保留为四类基础设施：审核输入和选源、原始观察身份、观察关联的关系原语、未知／预算／成本记录。它尚未形成以下方法对象：目标相关的完整候选解释、条件化分支规格、跨分支共同约束、证据分级，以及相对于声明边界的路径覆盖结论。

因此，下一步不是扩写一个完整符号执行器，也不是把所有关系交给 LLM 自由拼接。最小正确演进应在现有关系层之上增加一个**解释与规格组合层**，并把不能通过调用上下文、时序和覆盖反例的关系限制为候选或未知。

## 现有实现的处理结论

### 保留

1. 冻结输入、源码角色、预算和哈希留证。
2. 原观察身份与逐观察失败隔离。
3. Python 已验证的调用绑定、值流、分支方向、状态候选／未知／排除原语。
4. Java 的结构类型证据、观察种子、调用候选、堆效果按需证据和所有前沿记录。
5. 通用结果契约中的来源、关系原语、未知、成本和语义核验状态。

### 限制

1. Java `ab949d5` 的跨过程数据、控制和异常路径只能作为候选或未知，不能作为条件化依赖行为约束。
2. Python 的 guard、return、exception 和 state 行必须组合成连续解释后，才可成为分支规格；单条关系不代表路径成立。
3. `backend complete`、全部观察映射、跨源关系数量和图可达性仅是工程／候选指标。

### 待验证草案

独立 WIP 分支中的 WALA 调用／返回匹配修改试图导出精确调用点、可能目标和调用者 CFG，并进行有界栈搜索。它直接回应 r5 的根因，但仍需通过同目标错误调用点、较晚调用到较早观察、多目标歧义、正常／异常延续和预算前沿的独立门禁；通过前不能写入“已有能力”或恢复全量运行。

### 新增而非替换后端

应在关系证据之上增加版本化的解释与规格组合层，至少承载：

- 分析边界和原始测试目标；
- 候选解释及有序步骤；
- 原始条件表达式、真假方向和未解析符号；
- 解释完整性、成立依据与具体实现依据；
- 共同约束及其适用范围和跨路径依据；
- 条件化分支规格；
- 未展开区域、预算截断和覆盖完整性；
- 每项结论引用的底层关系、源码和假设。

这个组合层可以使用规则和后续 LLM 近似推理，但证据等级只能由可核验程序证据、明确假设和反例更新；LLM 自信度不得提升等级。

## 实施前的停止条件

在恢复分析代码开发或全量165例运行前，应先具备：

1. 版本化的研究输出契约，能机械区分候选解释、受支持分支、阻塞未知和已排除路径。
2. 一组真实案例与补充机制反例，覆盖返回值传播、覆盖、多分支、外部条件、状态、异常和时序误连。
3. 对 Java 已知错误路径的撤回规则，以及对 WIP 匹配草案的独立正／反门禁。
4. 固定版本下的评阅协议：只报告已核验关系、明确遗漏、未知和成本，不以“全绿”作为目标。

达到这些条件后，开发任务才能按方法缺口拆分；完整批次用于测量固定实现的能力边界，而不是驱动逐例补丁循环。
