# 七例标签交付对照

七例是 #35 的原六例与 #34 的 flask_308。每例各用三个全新上下文生成 Base 与 v2，各组 21 次。Base 也全部按标签协议重新生成。相同案例内共用遮蔽测试、可见源码、授权读搜工具、模型设置和槽位要求。v2 组再收到事实地图。Jib 的三次 v2 门禁计入正式矩阵，要求按原样接收全部三个候选才能继续。生成不接受执行反馈，格式错误或编译失败原样登记，拒绝按结果补跑以凑齐成功数。

两组均由宿主从动态定界符之间提取原样代码，再组成旧评估器接受的候选信封。标签自身的换行仅用作定界，保留 Python 相对缩进、空白行。标签交付率、原程序全过率及合格候选对三个同例变异的实际检出情况分别统计。参数化测试按完整候选确定资格。沿用 #35 已冻结的语义判据与变异判据，Flask 沿用 #34 及本目录上一级 rubric.md。

比较单位为案例，保留三轮原始值。附带报告各轮的输入与工具成本。与历史 JSON 的交付数比较仅属历史对照；新的 Base/v2 比较采用相同交付格式。没有随机效应或全量泛化估计。
