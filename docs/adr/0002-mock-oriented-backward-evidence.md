# 后向分析交付条件化 Mock 行为规格

从测试目标出发，通过后向切片定位相关程序逻辑，结合近似符号分析构造目标相关的候选执行解释，为各路径推导条件化的依赖行为约束，交付带有使用边界的 Mock 行为规格。在明确的分析边界内，尽可能准确地推导目标相关的依赖行为约束，并明确区分已确认的行为、依赖假设的行为和仍然未知的行为；一个观察可以存在多个合法执行解释。

规格保留三部分：所有合法路径必须满足的共同约束；各合法路径独立对应的条件化分支规格（依赖响应及交互行为）；支持这些结论的证据与不确定性。观察—依赖链和原始条件是推导材料，单独的切片或条件清单不等于最终规格。不把已发现路径的交集自动推广到全部合法路径。

完整解释原则：每条候选路径必须在声明的程序边界内完整解释目标相关的执行过程，交代关键依赖响应、交互和到达观察的关系，而不是只收集分支条件。外部调用允许摘要化，摘要中的未知仍保留；解释完整性不意味着枚举全部路径或已证明路径可行。

证据分级原则：路径被发现不等于路径成立。分别记录解释完整性和成立依据，区分已有程序证据支持、依赖明确假设、存在阻塞性未知及已被反例排除的情况；只有足够证据支持的路径才可成为 Coding Agent 的可选生成依据。未发现矛盾和 LLM 自信度都不能作为路径成立或证据升级的依据。

条件不可求解原则：允许交付含未解析条件的条件式规格，保留原表达式、已知用途和证据缺口；未知条件不得包装成可直接实现的具体依赖响应。解释完整、路径有依据和已具备具体实现依据是不同判断。为了让 Coding Agent 产出 Mock 代码，不得将不确定推测伪装为确定程序语义；只能在获得新的可核验依据后修订相应结论。

非目标：不保证唯一执行路径，不保证枚举全部可能路径，不保证求解全部外部依赖的具体响应，也不要求每种 Mock 行为具有唯一实现。以上边界不豁免错绑调用、错误数据传播或已被反例否定的关系。

规格同时记录全局路径覆盖信息：声明探索边界、已探索候选、已知未展开区域、截断和未解决分支，并明确覆盖完整性未知的情况。全局是相对声明的任务与程序边界，不默认掌握全部路径集合；没有可核验的分母时，不报告全部路径覆盖百分比。

整体研究流程为后向切片、近似符号分析、LLM 约束推理、Mock 生成和执行验证。第二篇工作的候选方法设计是在明确程序边界和证据约束下推导、区分并利用多种依赖行为解释；该定位不构成已验证的新颖性或有效性结论，也不扩展下述本轮实施范围。

本轮只交付和验证后向分析：检查观察—依赖链、局部约束、源码证据及排除误连的反例。Mock 生成、Agent 消费对照、Mock 合法性评分及缺陷检测实验留到后续，不属于本轮实施或验收范围。此次范围澄清取代先前将小规模 Agent 对照纳入本轮的决定；生产契约和生产 Agent 的职责保持既有边界。

方法边界是从测试观察向后提取相关值来源、调用关系与分支条件，整理为观察相关路径约束，供后续 LLM 结合代码上下文近似推理。不追求完整符号执行或所有路径条件的精确逻辑化，不依赖 SMT 求解；遇到外部 API、复杂对象、第三方库或环境表达式，保留原表达式、绑定上下文、已知用途及未知，不强行求解或丢弃。

分支方向、条件适用的候选路径及其关联依据必须保留；互斥候选分开表达，不把切片内所有条件直接合取。未证明路径可行时明确标记，不把原始表达式或 LLM 推测称为已证明可满足的约束。表达式语义可以暂不解释，但错绑调用、跨调用上下文误连和赋值覆盖错误仍属于分析缺陷。本轮交付分析及规格，近似推理的实现方式由后续实施规格明确，不实现下游 Mock 代码生成流程。

局部证据可以交付，未解决的未知必须同时保留，不把猜测提升为分析器已证明的约束。分析失败、无法确定和预算截断的案例保留在统计中。未来消费者可据此继续查询或决定如何使用；本轮不实现其生成流程。

后续若进行 Agent 消费实验，沿用已讨论的配对对照原则：相同案例、模型版本、原始输入、源码访问权限和生成／修复预算，实验组额外获得分析证据，分析成本另计。该原则不是本轮执行授权或完成条件。

沿用 ADR-0001：当前 MUT 不是业务正确性的证明，实现事实、测试要求、依赖约定和推导结论分别留证，冲突不可用不合理 Mock 消除。方法原则与本轮范围已达成一致；支持范围、预算及可执行证据验收标准需在实施规格中具体化。本决定不表示实现已完成，也不授权恢复此前暂停的自动修复与全量复跑。
