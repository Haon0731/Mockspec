# Step 6.4 — 运行可审计且受预算门禁约束的推理

发布状态：拆分已确认；目标仓库 Haon0731/Mockspec。仅任务 01 初始标记 ready-for-agent，其余任务在全部阻塞项完成后开放。

## What to build

研究者从宿主运行入口选择版本与预算，获得包含成功或失败全过程的独立产物；下一次模型请求受 Token/费用门禁约束。使用源码工具即可离线验证全链路，不依赖两种分析后端完成。

## Acceptance criteria

- [ ] 保留默认 V0.1 和冻结核心，通过宿主增加审计与实验控制，不覆盖历史产物。
- [ ] 记录模型/Prompt/代码/SDK 身份、任务与 snapshot 身份、采样和限额设置、时间、原始模型响应、实际工具调用参数/结果/状态/顺序及耗时。
- [ ] 成功产物只包含正常生成且通过现有 Validator 的有效 Contract；失败产物保留错误类别、已有轨迹及用量，不伪造 Contract。
- [ ] 运行前估算，逐次累计 Token 与费用，后续请求前实施门禁；超时、轮次和费用门禁停止后没有额外收尾模型调用。
- [ ] 费用记录包含计价依据与可得用量；未知值明确未知，不记为零，不把本地取消或事后统计说成严格费用硬上限。
- [ ] 单工具失败不自动否决合法 Contract；incomplete/unresolved 与无依赖严格区分，轨迹保留失败。
- [ ] 提供全轮共享预算/尝试记录机制或明确可执行的宿主门禁流程：目标 US$5，最多 4 次有效对照运行、全轮最多 2 次技术故障重试，失败与重试费用计入；不按结果质量重试。
- [ ] 记录并约束 SDK/传输层重试，避免隐式重试导致次数和费用不可审计。
- [ ] 离线测试验证成功、零工具、工具失败恢复、全局耗尽、验证失败、未知用量和产物不可覆盖；离线/live 模式标签准确。
- [ ] 给出正式实验前冻结配置和调用方式；此任务不消耗正式 live 对照次数。
