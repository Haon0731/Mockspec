# Step 6 交付报告

Scenario Inference Agent V0.2 已实现，工程回归与离线 SDK 集成通过。当前环境没有注入模型 ID/API Key，未进行 live inference：**自主工具使用尚未验证，场景质量提升或退化均未测量**。本报告完成规格允许的离线交付分支，不宣称真实推理端到端验收完成。

## 实现与边界

- `inference_v02.py` 使用现有 Agents SDK 注册三个 Function Tools；完整 UnifiedTask 初始输入与 V0.1 相同，允许零次调用。独立 Prompt，不改 Contract Schema/Validator。
- CLI 默认 V0.1，显式 `--agent-version v0.2` 选择新版。相对 `f699554`，V0.1 核心、Prompt、历史实验与合成示例保持不变。
- `program_tools.py` 仅从已审核任务的内存 SourceStore 查询 source_id 与合法行范围。Python AST/Spoon 只分析可见文本，不执行目标源码、不读取额外目标文件。
- Python/Java 解析使用可信子进程、清理后的环境和临时输入；超时/取消会终止并回收进程。Java 仅编译随包可信 helper；固定 Spoon JAR SHA-256，不自动下载。
- 结果保留原文件行号、引用、事实类别、限制和诊断。未解析名称、部分结果、unsupported 和分析错误不能解释为不存在依赖。语法嵌套和局部声明引用不证明数据流或路径可行性。
- 核心负责轮次、调用次数、输出大小及总时间限制；`budget.py`、`experiment_ledger.py`、`live_v02.py` 负责费用门禁、留证、全轮预算与技术重试。没有案例专用推理分支。

默认上限：6 轮、8 次工具调用、每响应 4096 输出 Token、累计/估算 24000 Token、每工具 16000 字符、每次解析 15 秒、全局 120 秒。费用需要宿主提供核实后的费率；预算门禁不是远端账单硬上限。未知用量不会记为零；已发出但未完成请求使核算不完整并阻止后续实验。

正式账本固定四个案例/版本槽位，最多两次技术故障重试、US$5 目标；不允许按质量重跑。配置指纹包括输入、两版 Prompt、基线/共享代码、审核清单、SDK、Git 和可获得的解析器/运行时身份。V0.1 冻结意味着其传输重试和输出限制与 V0.2 有必要差异，产物明确披露；不能宣称完全相同的运行条件。

## 验证与证据

最终两案例产物在 [evidence/final](evidence/final)，复现命令见 [reproduce.md](reproduce.md)。`evidence/python`、`evidence/java` 保留审查修复前的离线 SDK 验证；不覆盖历史记录。最终产物记录代码 SHA-256、提交、dirty 状态、SDK 与运行时身份。

每个案例对两个版本各执行一次脚本 SDK 流程。V0.1 无工具；V0.2 的脚本模型请求三个工具，SDK 实际调用源码查询、AST/Spoon 结构分析和依赖使用分析，然后接收工具结果并验证已有合成 Contract。调用轨迹是真实工具执行记录；工具选择及最终 Contract 是测试脚本/既有 fixture 提供，**不是模型自主决定或 live 推理产物**。

两个版本初始序列化输入一致，Contract 通过现有结构与证据位置 Validator。它只证明集成与引用合法性，不证明语义正确性。全轮没有 provider 请求、没有技术重试、provider 费用 US$0；实际模型 Token 未测量。轨迹中的 scripted usage 是测试占位值，不可作为 Token 开销。

最终测试为 **189 passed，0 failed，0 skipped（18.95 秒）**，构建和冻结核对结果记在 [verification.json](evidence/verification.json)。覆盖零调用、工具失败后继续、调用预算耗尽不收尾、未知/部分用量、全轮重试/费用门禁、输入越界、源码偏移、截断、Java 不支持语法、子进程超时/取消及真实 SDK 工具循环。项目没有配置独立 lint/typecheck 工具；本轮运行编译检查、diff whitespace 检查、全套 pytest 和安装 wheel 的解析冒烟。

最终 Python 离线 V0.2 流程耗时约 0.243 秒，结构工具返回 20 项事实、依赖工具返回 18 项；Java 约 4.593 秒，结构返回 33/63 项、依赖返回 31/58 项，两者均显式 incomplete。耗时包含 SDK 脚本循环与解析执行，不是模型延迟；单次本地测量不能用于性能普遍性结论。

## 独立审查

两个独立 reviewer 分别依据仓库标准和规格审查，修复后对原发现复核。

| 审查轴 | 发现 | 处置 |
| --- | --- | --- |
| Standards | Java 未支持结构可能被当作完整结果 | loop/switch/lambda 显式 unsupported 并返回 incomplete，增加回归 |
| Standards | 零请求已知零费用与未知费用混淆 | 配置费率且未发请求记零；已发未完成保留未知，增加回归 |
| Standards | Git 身份受调用工作目录影响、代码身份不完整 | 锚定模块所属项目，覆盖基线、共享模块和准入清单；仓库外安装明确未知 Git |
| Spec | 仅 raw_usage 元数据或 total_tokens 可能被记为已知零费用 | 无输入/输出拆分时标未知，阻止后续调用，增加回归 |
| Spec | Python 同步 AST 不遵守可中止的分析时间限制 | 改为可取消子进程，验证终止与回收、环境隔离和不执行源码 |
| Spec | 正式配置未绑定全部代码/运行时身份 | 加入 Git、Python、Spoon/JDK/Javac 可得身份及代码哈希 |

这些是工程缺陷及修复，不是模型质量退化。Java 管道等待在本地环境曾无法及时结束，改为文件型进程输入输出与有界轮询；最终实际 Spoon 流程通过。JUnit/目标项目测试和旧 Stub-Tester 实验未执行。
