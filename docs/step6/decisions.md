## 工程验收与研究效果

- 工具调用、输入隔离、证据验证和真实推理流程正确实现时，可以判定工程交付完成，即使场景质量未改善或退化。
- 客观记录退化原因，区分工程错误与模型推理局限；无法确定原因时明确保留不确定性。
- 修复工程错误；不得为了改善实验结果反复调整 Prompt。

## 自主工具使用

- V0.2 允许零次工具调用，研究对象是 Agent 自主决定何时需要程序分析证据。
- 两个真实案例都未调用工具时，记录“自主工具使用尚未验证”，不得宣称该能力已通过端到端验证。
- 可另设独立诊断案例验证工具调用能力，但强制调用、宿主预调用不得视为自主行为；诊断运行的预算分配待确认。

## 最小对照实验

- Java JarFiles 与 Python flask_308，V0.1/V0.2 各一次，共 4 次有效运行。
- 最多 2 次技术故障重试；不因结果质量不好重试。
- 总费用目标上限 US$5，采用运行前估算、逐次记录和预算门禁。
- 若无法实现严格硬上限，必须说明，不能宣称具有硬预算保证。
- 尽量固定模型、输入和采样配置，记录额外 Token 与执行成本。
- 历史 V0.1 结果可作参照；正式公平对照需核对模型版本及运行条件，必要时重新运行。
- 模型调用不可用时只做离线验证，明确实际验证范围，不能将回放视为 live inference。

## 保留与范围

- V0.1 Prompt、代码和历史实验结果冻结；V0.2 独立版本，不覆盖基线。
- 仅实现 Scenario Inference Agent 工具增强与小规模验证。
- 不修改 Stub-Tester，不接入 Joern，不扩展数据集，不实现 Mock Generation 或 Behavioral Feedback。
- 原 `inference.py` 和 V0.1 Prompt 逐字冻结，新增 `inference_v02.py`；允许少量重复代码，不为抽象复用改动基线核心。
- 宿主 CLI 增加版本选择，默认 V0.1；复用 Agents SDK、UnifiedTask、Scenario Contract 和 Validator。
- V0.2 初始获得与 V0.1 相同的完整可见 UnifiedTask。工具只提供已有可见源码的分析事实，不扩大信息范围，不引入按需获取初始源码的实验变量。

## 失败与预算耗尽

- 单个工具失败返回明确错误状态及诊断；Agent 可以在剩余预算内继续推导，不能确定的行为标记 unknown。
- incomplete/unresolved 不等于没有相关调用或依赖。
- 全局时间、轮次或费用门禁触发后停止，不增加收尾模型调用。
- 正常生成且通过现有 Contract Validator 的输出才算有效 Contract；工具失败记录仍须保留。
- 失败运行保留调用轨迹、错误类别、Token 和成本，不伪造 Contract。
- 具体运行限额和模型配置须在正式实验前冻结并记录；未确认的数值不视为用户决定。
