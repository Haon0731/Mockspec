# 自包含依赖规格示例

这些 JSON 由固定假响应经过当前 staged-inference 控制器生成，输入和答案都是人工构造的合成材料。
它们展示交付协议与语义参考，不是经过真实 Adapter 审核的项目输入，也不是模型推理成功证据。
复现与关系验收位于 [test_staged_semantic_loop.py](../../../tests/test_staged_semantic_loop.py)。

## 多个合法 Mock

[product.json](product.json) 固定同一业务标识，接口要求 `p` 是正整数、`q` 是非负整数。
真实 MUT 在 `q=0` 时返回 0，否则返回乘积；测试要求 100。规格保留接口条件并要求
`q>0`、`p*q=100`，没有固定某个因子对或增加调用次数验证。

| 具体化 | 是否符合本场景规格 | 理由 |
| --- | --- | --- |
| `p=20, q=5` | 是 | 接口条件与乘积关系均成立 |
| `p=25, q=4` | 是 | 同一关系的另一合法实例 |
| `p=20, q=4` | 否 | 结果为 80 |
| `p=-20, q=-5` | 否 | 即使乘积为 100，也违反接口条件 |
| `p=10, q=0` | 否 | 进入返回 0 的真实分支 |

下游可以用常量返回、查表或其他实现满足同一关系。合法性不依赖具体 Mock 框架，
也不表示这些 Mock 对每种错误 MUT 具有相同的区分能力。

## 关键未知限制消费

[adjust-unresolved.json](adjust-unresolved.json) 在非零分支保留真实 `adjust(p*q)`，
其行为不在本次初始片段范围内。规格交付 `adjust(p*q)=100` 的关系片段，
但 `delivery_status=partial`，未知项绑定原始目标、约束和分支。
它没有声称 `p*q=100` 已充分，也没有宣称存在可行取值；生成器不能将其作为完整配置依据。
如授权仓库可取得 `adjust`，控制器的补查测试会读到 `adjust(x)=2*x`，再把关系更新为 `p*q=50`。

两个文件都自带任务输入、固定条件、替换边界、正式契约、依据、允许变化、未知影响、
回归参考假设和停止摘要；无需重新解释 `inference_record.json`。
`input_origin=synthetic_fixture` 明确其来源。`ready` 是有依据的模型交付判断加机械一致性校验，
不代表宿主已经证明所有自然语言约束正确。
